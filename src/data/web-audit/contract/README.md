# Web-audit vendoring contract

The one directory `brettdavies/agentnative-cli` vendors for `anc web`: data generated from this repo's registry, fix
catalog and engine, plus the fixtures that pin the engine's behavior. The CLI reads these files instead of this repo's
sources, so no site module's layout reaches another repo.

## Layout

```text
src/data/web-audit/contract/
  README.md                     this file, site-only
  .editorconfig                 keeps editors off the generated bytes, site-only
  build/                        generated, compiled into the CLI
    FINGERPRINT                 one line: the value `anc web`'s staleness note compares
    constants.json              user agents, engine settings, registry fingerprint
    registry.json               normalized registry, as emitWebAuditRegistry writes it
    remediation.json            normalized fix catalog, as emitWebRemediation writes it
    server-card.schema.json     the vendored SEP-2127 schema, byte for byte
  test/                         test inputs, outside the CLI's published crate
    score-parity.json           hand-authored scoring cases
    conformance/                generated golden corpus and request sets; its README.md is the format contract
```

## Consumers

| Consumer                                      | Reads                                                                        |
| --------------------------------------------- | ---------------------------------------------------------------------------- |
| `agentnative-cli` `scripts/sync-web-audit.sh` | `build/` into `src/web_audit/vendored/contract/` at a pinned site commit     |
| `agentnative-cli` `scripts/sync-web-audit.sh` | `test/` into `tests/fixtures/web-audit-contract/` at the same commit         |
| `src/build/13-web-audit-registry.mjs`         | `build/FINGERPRINT` into `dist/_internal/web-audit-contract-fingerprint.txt` |
| `.github/workflows/deploy.yml`                | `build/FINGERPRINT`, as the value the post-deploy smoke waits for            |
| `tests/regression.test.ts`                    | `build/`, compacted, against the shipped `dist` files                        |
| `tests/web-audit-conformance-corpus.test.ts`  | `test/conformance/`                                                          |
| `tests/web-audit-two-score.test.ts`           | `test/score-parity.json`                                                     |
| `tests/web-audit-global-universe.test.ts`     | `test/conformance/scenarios/auth-own-endpoint/scorecard.json`                |

The Worker reads the files the build writes under `dist/_internal/`, never this directory: a registry and a fix catalog
projected from their sources, and the copy of `FINGERPRINT`. `build/` keeps the readable JSON the emit step writes, so a
registry change reads as a short diff in both repos, and `minifyDist` then compacts the `dist` copy.
`tests/regression.test.ts` holds the compacted `build/` bytes equal to the shipped `dist` files.

## Regenerating

One command writes every generated file:

```bash
bun scripts/web-audit/gen-fixtures.ts
bun scripts/web-audit/gen-fixtures.ts --check   # exit 1 naming each stale file; writes nothing
```

**A change to the registry, the fix catalog, the vendored server card schema, a conformance scenario, an engine setting
or the requests the engine sends regenerates the contract in the same PR.** `tests/web-audit-contract.test.ts` runs in
`bun test` and fails the PR otherwise, naming the stale file and this command. Never edit a generated file by hand.
`test/score-parity.json` is the one hand-authored file: edit it directly, with its test.

The CLI picks up a regenerated contract only when it moves its pin, and tests against the contract it holds until then.

`.github/workflows/web-audit-cli-parity.yml` runs on each PR that changes this directory: it builds CLI `dev` against
the PR's contract and reports, in a job summary and one PR comment, what the CLI's next bump will carry. The report is
informational and in no ruleset.

## Settings and request sets

`build/constants.json` holds the user agents, the registry fingerprint and the engine's concurrency, timeouts,
deadlines, caps and limits, under the name its owning module exports each by, so one search finds it in both repos.
Export a new one from its owning module and add it to `contractConstants` in `scripts/web-audit/contract.ts`; never
restate a value by hand. The scoring weights, the broken factor, the noncompliant credit and the web schema version stay
out, because the corpus scorecards already pin them and `test/score-parity.json` pins the scoring rule.

The site engine reads the root and some documents with no byte cap, so the file carries no root-read ceiling. The CLI's
16 MiB root-read cap is its own, a known divergence on a body larger than that.

Each scenario's `requests.json` records every request the engine sent. Generation fails when a scenario sends one
request twice, and when its scorecard or request set at concurrency 1 differs from the default run.

## Fingerprint

`build/FINGERPRINT` is one line: the first 12 characters of a sha256 over every other file under `build/` and `test/`
except any `README.md`, in path order, each as its path, length and bytes. `/api/web-audit/version` serves it as
`contract_fingerprint`, the value `anc web`'s staleness note compares. The file ends in a newline and the endpoint
serves the 12 characters, so compare the trimmed value; the CLI never computes the hash.

It moves when any hashed byte moves. A scorecard or request set moves when engine behavior does, which
`registry_fingerprint` cannot see. A setting, a fix-catalog edit or a scenario's own text moves it too, so a difference
means the mirrored data differs, not necessarily that behavior does. A logic change no scenario reaches moves nothing,
and neither does one on a deadline path, because the corpus runs under a frozen clock. A prose edit to any `README.md`
moves nothing, so an older CLI does not report a difference over prose alone.

Each deploy job waits for the endpoint to serve the value from the tree it deployed
(`SMOKE_EXPECT_CONTRACT_FINGERPRINT` in `scripts/smoke-web-audit-version.sh`). On a deploy that moves the value, an
isolate still on the earlier deployment cannot pass in its place; a deploy that leaves the value alone can pass on that
isolate's identical answer.

## Changing the shape

`CONTRACT_LISTING` in `src/build/web-audit-contract-paths.mjs` pins the entries of this directory, `build/` and `test/`,
and that module owns every path here. The CLI's sync maps `build/` and `test/` whole, so a new entry is a change to the
CLI's inputs: pin it in the same PR, and a test fails until you do.

Biome, markdownlint, Vale, `scripts/prose-check.sh`, `.gitattributes` and the `.editorconfig` here all leave the
generated bytes alone. A new formatter in the toolchain needs the same exclusion.
